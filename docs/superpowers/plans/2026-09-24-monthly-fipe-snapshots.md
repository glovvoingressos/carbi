# Monthly FIPE Snapshot Refresh Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Automatically refresh FIPE price/month snapshots for active listings from the privately stored plate lookup, without fetching FIPE on public page views.

**Architecture:** A daily production Vercel Cron calls an authenticated Next.js route. The route selects due private vehicle identifiers linked to active listings, makes a bounded number of Placa API lookups, accepts only a positive FIPE price with a parseable and newer month, updates all active listings for the vehicle, and persists retry/backoff state. Failures preserve the last good price and schedule a later attempt.

**Tech Stack:** Next.js App Router Route Handlers, TypeScript, Supabase service-role client, Postgres migration/RLS, Vercel Cron, Placa API, Vitest.

**Spec:** `docs/superpowers/specs/2026-09-24-monthly-fipe-snapshots-design.md`

## Global Constraints

- Query only active listings and only through private vehicle identifiers.
- Deduplicate by `vehicle_id`; one plate lookup updates all active listings for that vehicle.
- Never expose or log the full plate, private API response, or API token.
- Never replace a valid snapshot with a missing, invalid, equal, or older FIPE reference.
- Keep the existing server-only Placa API integration; do not add a public FIPE lookup on page render.
- Fail closed when `CRON_SECRET` is absent or invalid.
- Keep each Cron invocation bounded by a configurable batch limit and persist work state so future daily invocations can resume.
- Preserve existing unrelated working-tree changes; stage only files owned by this feature if a commit is requested.

## Review Focus

- Missing/unparseable month or FIPE amount: preserve current listing snapshot; pin with service tests.
- Equal/older provider reference: do not overwrite; pin with reference-comparison tests.
- API quota/429 and transient network errors: persist retry state, no page error, no overwrite; pin with service and route tests.
- Multiple active listings for one vehicle: one provider request, all active listings updated, inactive listings untouched; pin with route/service tests.
- Unauthorized or missing cron secret: return 401/503 without database or provider calls; pin with route tests.

```ts
export async function GET(request: Request) {
  const secret = process.env.CRON_SECRET
  if (!secret || request.headers.get('authorization') !== `Bearer ${secret}`) {
    return Response.json({ error: 'Não autorizado.' }, { status: 401 })
  }
  const limit = parseBatchLimit(process.env.FIPE_REFRESH_BATCH_SIZE, 25, 100)
  return Response.json(await runFipeRefreshBatch({ limit, now: new Date() }))
}
```
